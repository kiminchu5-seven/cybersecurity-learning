# TryHackMe Pre Security

This section documents my hands-on learning and practical exercises completed through the TryHackMe Pre Security learning path.

## Overview

The Pre Security path introduced the fundamentals of cybersecurity through interactive tasks and a controlled virtual lab environment. I learned about offensive security, defensive thinking, identifying information from web applications, and understanding how vulnerabilities can affect a system.

---

## Task 1 — Thinking Like a Hacker

### Objective

The first task introduced the concept of **offensive security** and encouraged thinking from an attacker's perspective.

The objective was to understand how a hacker may look for weaknesses in a system and how security professionals can identify and address those weaknesses before they are exploited.

### What I Learned

* Offensive security focuses on identifying weaknesses from an attacker's perspective.
* Understanding how attacks work helps security professionals design better defenses.
* Security testing can be performed in controlled environments to identify vulnerabilities.
* Thinking like an attacker can help organizations strengthen their security mechanisms.

### Key Takeaway

> Understanding how an attack could happen is an important part of building an effective defense.

## Task 3 — Exploring URLs and Web Application Functionality

### Objective

The third task involved working with two URLs provided by the lab:

* Bank Transfer
* Bank Account

The objective was to understand how different parts of a web application interact and how information from one part of the application could be used in another.

### What I Did

* Examined the URLs provided by the lab.
* Accessed the bank account section.
* Identified that the account had a negative balance.
* Used the bank transfer functionality provided by the controlled lab environment.
* Entered the required bank account information and transfer amount.

### Lab Account

**Account Number:** `8881`

### What I Learned

This exercise helped me understand that web applications may contain weaknesses in how different functions interact with each other.

It also demonstrated why applications need proper validation and authorization controls for financial operations.

## Task 4 — Identifying the Result of the Vulnerability

### Objective

The final task required me to observe the result produced by the vulnerable banking application after performing the required actions in the lab.

### What I Did

* Used the bank transfer functionality in the authorized TryHackMe environment.
* Entered the required account information.
* Performed the transfer with the specified amount.
* Observed the response generated by the application.

### Result

The application displayed a **"Bank hacked"** message.

This was the required answer for the final fill-in-the-blank task.

### What I Learned

The exercise demonstrated how a vulnerable web application's functionality can potentially be manipulated when appropriate security controls are not implemented.

# Key Takeaways

1. Cybersecurity requires understanding both offensive and defensive perspectives.
2. Web applications should not expose unnecessary sensitive information.
3. Financial operations require strong validation and authorization controls.
4. Vulnerabilities can arise when different application functions are not properly secured.
5. Controlled environments such as TryHackMe provide a safe way to understand security vulnerabilities through practical exercises.
